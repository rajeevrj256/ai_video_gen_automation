# Context for Claude Code sessions

This repo holds two video tools for 9:16 short-form video. Read `README.md` for the
user-facing overview. This file covers what a new session needs in order to work
fast on the user's own machine, and the traps that have already cost time.

- `ai-reels-generator/`: **Reel Studio** (Python + a Remotion editor). Fully automatic
  trend → script → fact-check → voice → footage → Remotion edit → verify pipeline,
  with a local web app. Its own README has the details.
- `remotion-studio/`: **Remotion Studio**, hand-built motion graphics, imported from
  `rajeevrj256/remotion_claude_generation`. It has its own `CLAUDE.md` with traps
  specific to it (named `Layer` instead of `AbsoluteFill`, the canvas editor, the
  OneDrive patches). Follow that file when working in that folder.
- `calculator/`: the repo's original React calculator, unrelated. Leave it alone.

Working branch: `claude/ai-auto-generate-reels-shorts-muhsa4` (GitHub repo
`rajeevrj256/ai_video_gen_automation`, formerly `calculator`).

## Commands

```bash
./start-all.sh                      # or start-all.bat: Reel Studio + Remotion Studio + layout server
cd ai-reels-generator
./start.sh                          # Reel Studio only (first run creates .venv, npm installs remotion/)
.venv/bin/python -m reelgen --count 1 [--topic "..."]     # Windows: .venv\Scripts\python
cd remotion && npx tsc --noEmit     # typecheck the reels editor
npx remotion still src/index.ts Reel out.png --frame=60   # render one frame of the demo props
cd ../../remotion-studio && npm run studio / npm run typecheck
```

## How Reel Studio works (ai-reels-generator/reelgen/)

| File | Role |
|---|---|
| `pipeline.py` | The loop: write → `check_script` → `fact_check_script` (fixes up to 2×, no attempt used) → voice → footage → render → `check_video` → `review_with_claude`. Up to `REEL_MAX_ATTEMPTS` tries; the best attempt is kept. |
| `shortfix.py` | **Shorts token savings** (Shorts only; long videos use `longform.fix_long_script`). `fix_scenes` changes only the flagged scenes (and the on-screen hook as scene 0), keeping sounds and transitions; `fact_check_scenes` re-checks only the changed scenes (marked `>>`). `pipeline._make_video` uses them for fact-check fixes, rule breaks found by `check_script`, a voiceover over 30 s (trim and re-record, up to 2x) and a failed review (checkpoint stage `revise` with `review_issues`/`review_fix`: the next attempt fixes those scenes, re-checks them, re-voices, re-downloads footage and re-renders; never a new script). A Short used to cost ~1.2M tokens: every fix wrote a whole script with research and fact-checked all of it again. Only scenes whose words or figures changed are re-checked (`claims_changed`; new footage queries need no fact-check, and a footage-only review fix keeps the narration); a re-check searches the web only when the fix brings a new figure or name (`new_facts`), otherwise the earlier findings are its evidence; fact fixes follow the checker's instructions without searching again. A revise after still-unconfirmed facts (`revise_facts`) that changed no words re-checks the whole script. |
| `repeats.py` | **Never the same video twice, every pipeline** (a broad typed topic once made the same QR-code long video twice, 5 hours each): `made` = every library report (title, subject, topic, premise) + `<output>/subjects.json` (claimed as soon as a script exists, so parallel and failed videos count); `prompt_block` goes into the Shorts and long writers' prompts; every format counts against every other (`EVERY`: a medium video on the barcode repeated a barcode Short); a typed topic is first narrowed to one new subject by `narrow`/`choose_subject` (small call, no web, low effort: Claude lists 8 subjects, code drops the repeats and picks one at random, since asked for one it gave the same famous example every time; 3 tries, then the job stops before spending more; the pick is claimed at once (`_mine` keeps guard from flagging the video's own claim)); `too_close` also matches the subject's core (`_core`: the phrase before ':', 'and', 'why'...), and older Shorts' subject comes from `script.json`; the news style skips narrowing (the writer searches this week's news); `guard` checks a freshly written script (`too_close`: one subject inside the other's subject+title, or ≥40% word overlap) and writes it once more with the reason, else stops before voice/footage/render, then `claim`s it. Script Videos are only flagged in the log; Stick has its own check (`stickstory.made_before`). Shorts reports now carry `subject`. |
| `script_writer.py` | `system_prompt(style)`: shared rules + a block per `video_style` (`facts` true stories, fact-checked; `news` = facts plus `news_rules()`: one real story from the last 7 days, confirmed by two outlets or the primary source, says when, no politics/wars/crime/gossip, also for long videos; `TRUE_STYLES` decides fact-checking; `story` fiction; `comedy` jokes; `mix` rotates facts/story/comedy per video in `pipeline.run`). Fact-check runs only for `facts`; the review rubric and post text adapt per style. `ReelScript` schema (`hook_question`, `answer`, scenes, `visual_queries`, `graphic`). Every video is one story around one question: a hook of 12 words or fewer (question, hidden origin, contradiction...), scenes linked by but/so, the answer only at the end. Topic rules, AI-cliché ban list, stock-footage query rules. |
| `llm.py` | Claude via the logged-in `claude -p --json-schema` CLI (no API key) or the Anthropic API. Model `claude-opus-5-5` at effort `high` by default (`CLAUDE_MODEL`, `REEL_CLAUDE_EFFORT`, or Settings). Not `CLAUDE_EFFORT`: Claude Code sessions set that name themselves. Fact-checks (Shorts `fact_check_script`/`fact_check_scenes`, long `fact_check_long`) use their own `fact_model`/`fact_effort` (default `claude-sonnet-5-5` at `medium`; `REEL_FACT_MODEL`, `REEL_FACT_EFFORT`, or Settings): they search and compare claims with sources and were ~45% of a long video's tokens. Fixes, scripts and reviews stay on the main model. |
| `verify.py` | Script checks, fact-check (web search), ffmpeg checks (≤30s, audio, black frames, captions), Claude review of a 6-frame contact sheet. |
| `voice.py` | edge-tts (online, exact word timings) with Kokoro fallback (offline ONNX, estimated timings). The whole narration is spoken in **one take** at a steady `REEL_VOICE_RATE` and cut into per-scene WAVs; per-scene synthesis made every scene end on the same falling tone and sounded like reading. Default voice `en-US-AndrewMultilingualNeural`. **Hinglish** (`hinglish.py`): a Script Video typed in Roman Hinglish and read by hi-IN-MadhurNeural came out with every English word mangled ('nesht kweshtan', 'sakshes', 'Intiya', 'afortibal'): the Hindi voices guess Roman text. `synthesize_scenes` now gives a Hindi voice (or a Multilingual one when `looks_hinglish`: ≥3 and ≥6% common Roman Hindi words, so English scripts never cost a call) the lines in mixed script, Hindi words in Devanagari and English words/names as written (`to_speech`: one Claude call on the fact model at low effort per batch of new lines, cached in `<output>/hinglish_cache.json`; a line whose word count changed is kept as written), and `_shown_as_written` puts the user's own words back on the spoken word timings by position (captions, cues). Kokoro gets the text as written. Setting `hinglish_mix` (default on; `hinglish.enabled()`) turns the mixed script off for every voice: the Script tab's voice-test checkbox saves it, so the video reads the text the way the chosen sample did. The Script tab's 'Try the voice on a line' (`POST /api/voice-test` → `/api/voice-test/<key>.mp3`, `<output>/voice-tests/`) plays one line with the chosen voice, mixed or as written, and shows what was spoken. Voices: Madhur, Swara (Hindi/Hinglish), Ava Multilingual added to the long voices. The free edge-tts service has no dedicated Hinglish voice (hi-IN: Madhur, Swara; en-IN: Prabhat, Neerja, NeerjaExpressive; plus the Multilingual ones). **Sarvam AI** (`sarvam.py`, the user's free key): voices `sarvam:<id>` in the long/Script voice list: bulbul:v4-flash IDs `<name>_<lang>_<style>` (`enhi` = English-Hindi code-mixed: shubh_enhi_ads, the one the user liked in Sarvam's playground, shubh_enhi_companion, simran/ishita/shalini_enhi_companion, sunny_enhi_customer; Hindi narration/news/stories voices) or bulbul:v3 speakers (`sarvam:shubh`); `POST https://api.sarvam.ai/text-to-speech` (header `api-subscription-key`, text ≤2500, language_code hi-IN, pace 0.5-2 from its own setting `sarvam_pace`, default 1.0 as in the playground setup the user liked: Bulbul v4 Flash, Shubh, Hindi, pace 1, loudness 1, pitch 0) returns base64 WAV with no word timings, so `scenes` speaks whole lines in takes of ≤2000 characters (0.3 s between takes), cuts each line at the real pause nearest its estimated end (`_pause_near`: ≥120 ms near-silence within 1.2 s, checked: every cut silent) and spreads each line's words over its own audio (`_estimate_words`); Sarvam's docs say romanized Hindi 'significantly reduces output quality', so Sarvam voices get the mixed script too (`hinglish.is_hindi_voice`); every take is levelled to -17 LUFS with peaks under -1.5 dBFS (`level_file`, ffmpeg ebur128 then a fixed gain): the user's app sample came out -13.4 LUFS / peak -0.3 against -17.4 / -1.3 for the same voice and text from Sarvam's playground and sounded different; the voice test is levelled the same way and takes up to 2000 characters (was 400, which cut the user's paragraph off); **Hook delivery** (setting `hook_delivery`: normal / lively / very, chosen by ear in the Script tab's voice test, which plays at the picked level): `sarvam.DELIVERY` = Sarvam `temperature` (expressiveness, default 0.6, not sent for normal) 0.75 / 0.9 and pace x1.05; only the long pipeline's hook take passes `delivery="hook"` to `synthesize_scenes`, chapters stay normal (one steady narrator; the hook already has its own take and trailer music); the free edge voices ignore it; no fallback to another voice mid-video; clear errors for a refused key and used-up credits, retries for 429/5xx. Key: Settings > Long videos 'Sarvam AI key' → `PUT /api/keys/sarvam` writes `SARVAM_API_KEY` into .env and the running app (`GET /api/keys` says only whether it's set). ₹3 per 1,000 characters. |
| `visuals.py` | Pexels search. Keeps only results whose page slug shares a word with the query. |
| `video.py` | Builds props and runs `remotion render` in `ai-reels-generator/remotion/`; falls back to moviepy. **Long compositions (Long, StickStory over `PART_FROM` 150 s) render in one-minute parts** (`_render_in_parts`: `render-parts/partNNN.mp4` + `.ok`, `--frames=a-b --muted`, the soundtrack once with `--codec=wav`, joined by ffmpeg concat without re-encoding (re-encoded once if parts came from two encoders), parts of a changed timeline discarded via `timeline.sha`; a finished part survives a crash, timeout or closed app and Resume continues from the next; `PART_TIMEOUT` 1 h per part instead of the old 4 h for the whole video, which killed a 4-hour Script Video render and lost everything; each part reports 'Editing: x of y min done · n frames/s · about m min left'). GPU encoding is tried on the first part and on failure the rest goes to the CPU (`_gpu_broken`, no full re-render). **Picture parts load no sound**: they render from `props-silent.json` (`silent: true`), and every sound goes through `remotion/src/Audio.tsx`, which draws nothing when silent. A `--muted` render still downloads every sound in the background, and one starting in a part's last frames failed a 1 h 39 min Script Video on part 11 with `ECONNREFUSED localhost:3001/.../rumble-lv.wav`. A failed part is tried again in a fresh process (`PART_TRIES` 3, the last with half the tabs), and the error shown is Remotion's first one (`_first_error`). Every render gets its own random port 20000-39999 (`_free_port`) instead of Remotion's first free one from 3000 (Studio sits on 3000). Never use `Html5Audio` directly in the editor: import `Audio` from `src/Audio.tsx`. Only a failure whose output names the encoder (`_gpu_error`: nvenc, CUDA, OpenEncodeSession...) switches GPU encoding off; before, any failed first try did (a page-load timeout on part 11 turned the GPU off for good), and the reason is shown. **The soundtrack is mixed by `soundtrack.py`, not Remotion**: ffmpeg decodes every sound and numpy places it with the editor's own rules (Sequence start frames, `Music` ducking/fades/mute, loops, ambience curve, cue volume and SPEECH_DUCK, per-frame volume), ~10 s for 10 minutes, ~0.9 GB peak (10 s blocks). Checked against Remotion's own wav on two long videos (hook, music start, ambience): same loudness in every 5 s window, offsets ≤16 samples, aligned correlation ≥0.98. Remotion's sound pass refused connections to its file server where many sounds start together (ECONNREFUSED on minute 11, three tries). **Change `soundtrack.py` whenever the editor changes how a sound plays.** If the mixer raises, the old way below runs. Old way: **The soundtrack is rendered in one-minute pieces too** (`audioNNN.wav` + `.ok`, joined by PCM concat, sample-exact), from `props-sound.json` (`soundOnly`: Long and StickStory draw no picture, so a frame only gathers sounds; identical audio, ~2x faster here) with the parts' browser, tabs, timeout and port (`_audio_cmd`); the old single `--codec=wav` pass had none of them and timed out after 1 h on an 11-min Script Video whose picture was already done. Every render passes `--timeout=180000` (`RENDER_TAB_TIMEOUT`; Remotion's 30 s default timed out 'Waiting for root component to load' on the busy laptop). `_concurrency`: REEL_CONCURRENCY, else every core capped by free RAM (~0.9 GB per browser tab: the user's 16 GB laptop at 84% used swapped with 8 tabs). `plan_transitions` keeps Claude's per-scene transition (flash/zoom/slide/glitch/fade) but forbids repeats and forces 2+ kinds. |
| `sfx.py` | Synthesised sounds, one per transition (whoosh, impact, swish, glitch, shimmer) plus a pop for graphics. No audio files. No riser of any kind: the built-in `riser` cue and the hook's `hook-riser` were removed after the user banned the hook riser ("delete hook-riser"), as boom/hit/rise were before. |
| `remix.py` | **Take a sound out of a finished video** (Effects & media used panel: 🗑 Remove from this video, `POST /api/videos/{id}/sounds/remove {name}`, job `sound_remove`): its cues dropped from props.json (a transition sound played by name points at `sfx/silence.wav`), the soundtrack mixed again (`soundtrack.mix`) under the same picture (`-c:v copy`), mastered; the first version is kept as `reel-original.mp4`; report `removed_sounds`. Only for compositions the mixer knows (Long incl. Script/Shoot, Anim, Toon, StickStory) whose sound files are all still there (`why_not`; the panel shows the reason instead of the button): a finished Short keeps only reel.mp4. The panel also has 🚫 Never use this file again for uploads (the library ban). Tested: two hook-riser hits taken out of a 48 s video, length and sound intact. |
| `longform.py` | **Long videos** (8-10 min, 16:9, fully animated, no footage): `LongScript` (chapters of beats, each a narration line + an animated visual), `check_long_script`, `fact_check_long` (fixes before recording: one full check with web search, then only the corrected lines are re-checked (`only=`, marked `>>`); after 2 fixes a strict fix drops what the sources don't all confirm; a script is never thrown away over facts, only over structure (length, chapter count, hook size: `GLOBAL_ISSUES`); `repair_long_script` fixes rule breaks in code first (a 4-word keyword becomes a title, surplus items trimmed) and other line-level rule breaks go to the targeted fixer, since one full rewrite costs ~500k tokens; claims still disputed go into the report as issues and the video is marked unverified; hook lines H1.. are checked too), one voice take per chapter (`long_voice`, default Andrew like Shorts (`config.DEFAULT_VOICE`; older saved settings are switched to Andrew once, `VOICE_MARK`), `long_language` Indian English), Remotion composition `Long` (`remotion/src/long/`), **preview review before rendering** (`_preview_review`: `preview_sheet` draws the same ~18 review frames straight from the timeline with `remotion/scripts/stills.mjs`, about 1-2 minutes instead of an hour-long render; Claude reviews them; if it fails, the flagged lines are fixed, fact-checked, re-voiced and previewed once more (`PREVIEW_FIXES`), then the video is rendered once; checkpoint `previewed` + `preview`; a preview that can't be drawn falls back to the old way). **The preview's review is the video's review**: after the render only the technical checks run (the final Claude review looked at the same frames, disagreed now and then and cost another full render); a new render only for a broken file, resolution or audio, never for review issues or a length outside 8-10 min (those go in the report). Without a preview: the final review on 2 frames per chapter (a failed review revises only the flagged lines: checkpoint stage `revise`, `review_issues`/`review_fix`, then only those lines are fact-checked, re-voiced and re-rendered; never a new script, which cost ~1.5M tokens), YouTube chapter timestamps in the description. Post text is YouTube-only (`LongPost`, no Instagram/Shorts): an SEO pass that researches search terms, picks a main keyword, keyword-first title, 150-char snippet, 150-300 word description, 3 hashtags, tags under 500 characters (`_fit_tags`). Jobs with `length: "long"` go to `run_long_batch`. **Medium** (`length: "medium"`, 5-6 min) is the same pipeline with `long_minutes = MEDIUM_MINUTES` (5.5; `server._long_cfg`): `shape(minutes)` sets the prompt's length, chapter count (4-5: a 30-45 s cold open + 3-4 chapters of 60-80 s), `check_long_script`'s chapter range, the review's wording and `check_long_video`'s accepted running time (4.3-7 min); the checkpoint keeps `minutes`, reports carry `length`. |
| Cinematic long videos | Every long video opens with the cinematic hook (`cinehook.py`, row below; videos made before it keep the old trailer: `TrailerHook` in `long/Cinematic.tsx`, letterbox, rays, slammed words) with its own trailer track (`music.trailer`: spy-pulse, ticking-clock, dark-pulse, glitch-drive). The main track is composed per video (`music.compose`: mood from the script, key/tempo/progression from a seed, layers follow each chapter's `intensity`, `drop` = silence then a hit) and starts where the hook ends (`musicFrom`); chapters can have an `ambience` bed. `variety.py` gives each video its own palette, backdrop and transition style (never the last few; `<output>/variety.json`) and tells the writer the recent moods. Every visual has a `camera` move and optional `impact` (punch-in, freeze + flash, shake, boom) handled by `Shot`; `scene` visuals are icon actors acting the line out (`long/Scene.tsx`). `sound_design.py` adds a sound for every visual action, timed to the animations (actor times are computed there and passed to the editor). Keyword/title slides are capped at 1 in 7 and never two in a row. Icon names go through `long/icon.ts` (lucide renamed many). |
| `scriptvideo.py` | **Script Video** (app tab "Script", `POST /api/script-video`, job `script_input`, length `script`): the user's own finished, fact-checked title, description, hook and script. The text is cut into lines in code (`parse_script`: paragraphs into 12-30 word lines at sentence ends, a long sentence split at a comma; chapter headings `## ...` or `Chapter N: ...` are kept; `parse_hook`: one shot per sentence, over 12 words split at a comma), so no spoken word ever changes (asserted). One Claude call, no web search (`storyboard`, rules sliced from the long writer's `_system` between "Show, don't write" and "Accuracy:"): a visual and sounds per line, chapters and their music, and the hook's shots (every hook line once, in order, plus up to 3 silent shots). **Words on screen** (`ScriptInput.screen_text`, the tab's 'Words on screen', default `english`): a Hinglish script was storyboarded with Hinglish slides ('Itni discussion kyun', 'Wajah'); now `SCREEN_ENGLISH` is added to the storyboard prompt (every headline, label, slam and card in short English, names/units as they are, numbers in digits, never Devanagari) and `BoardChapter.card_title` becomes the chapter card's `card_text`, while the user's heading stays the chapter title (YouTube chapters); the voice still reads the script as written; `script` keeps the old behaviour (text in the script's language, cards show the heading). Checked with a real storyboard of a Hinglish script: no Hindi word on screen. `assemble` builds an ordinary `LongScript` and `_long_loop` takes it with `manual` in the checkpoint at stage `scripted`: no writing, fact-check, preview review, Claude review or post text; voice, sound design, music, 3D/footage, render and technical checks are the long pipeline's own; the hook keeps its natural length (`SCRIPT_HOOK_SECONDS`, also in re-make and My voice when `report.source == "script"`); the running time isn't judged; a broken render is reported, never revised. The report keeps the user's title and description as written (`source: "script"`), with chapter stamps in `youtube_chapters`. Long videos are unchanged. |
| Story forms, sources, evidence | Long/medium scripts are told in one of `longform.STORY_FORMS` (investigation, chronicle, mechanism, comparison, myth-vs-record, decision; `LongScript.story_form`), chosen by the writer to fit the material, avoiding the last few (`variety.remember(..., form)`, `recent_block`), or set per job on the Create page (`story_form`, `cfg.story_form`). The old single skeleton (fixed trailer order, mid twist, open loops, answer at the end) and the prompt's example lines are gone: a templated storyline is what YouTube's inauthentic-content policy names. Visuals are evidence first (stat, chart, timeline, compare, steps, footage, 3D); icon `scene`/`icons` beats are capped at 1 in 3 and never three in a row (`check_long_script`, `ICON_TYPES`). `LongScript.sources` (3-10 pages the writer opened) are link-checked (`verify_sources`: a 404, dead host or redirect to the home page is dropped; 401/403/405/429 count as found) and listed in the description with CC BY credits (`with_sources`, before `Chapters:` so a re-make keeps them); report `sources`, `sources_unreachable`, `credits`. Fiction has no sources. |
| Backgrounds | Each chapter (`LChapter.backdrop`) and the hook (`LongScript.hook_backdrop`) has a stock-photo search for its real setting; `longform._plates` downloads a landscape Pexels photo for each (`visuals.pexels_photo`, same slug/alt relevance rule as footage), skipping the last 400 photos any video used (`<output>/backdrop_photos.json`, `variety.used_photos`), into `plates/` with the links in `look.plateUrls` (a re-make re-downloads the same pictures). `Backdrop` in `long/Cinematic.tsx` draws the photo darkened, softened, tinted with the palette and drifting (`Plate`); a part with no photo (no Pexels key, nothing found) keeps the abstract style. Listed in Effects & media used. The drifting backdrop uses a copy blurred and graded once (`_bake_plate`: `<key>-bg.jpg`, `look.platesBaked`; the per-frame CSS blur/brightness filter cost ~12-20% of a long render); chapter breaks keep the original photo. Same-voice re-makes copy the photos too. |
| Chapter breaks | No more one "CHAPTER N OF M" card: each break into a chapter has a style (`long/Breaks.tsx`: blackout = black, a beat, the line typed in, the chapter photo rising; lowerthird = documentary lower third with progress dots; trailer = letterbox and slammed glitch text like the hook; split = colour panel and photo; cut = 1.3 s punch), set by `longform.break_styles` (shuffled per video seed, neighbours never match, the first differs from the last video's; `look.breaks`, so a re-make keeps them; durations `BREAKS`) with a sound Claude picks per chapter (`LChapter.break_sound`: a name from the sound list, the user's files first when they fit, or `none`; empty = the style's role from `BREAK_ROLE`, the user's matching file else the built-in), added to the cues so it is levelled like every effect. The text is `LChapter.card_text` (a question or phrase Claude writes, else the title; Script Videos show your heading); it goes through the fact-check and review. Props without `style` (older videos) keep the old card. |
| Music variety (every pipeline) | `<output>/music_used.json` (`media.note_music`/`recent_music`): every video notes its uploads and composed moods. | Licences | Every uploaded sfx/music/3D file has a licence in `<folder>/licences.json` (`media.LICENCES`: own, royalty-free, cc0, cc-by, unknown; set on upload (the last pick is remembered, Royalty-free at first since most files come from Pixabay) or per file in Settings > Media library, `PUT /api/library/{kind}/{name}/licence`; all files at once, or only those still unknown, with `PUT /api/library/licences` → `media.set_all_licences`). `media._files` only returns files with a usable licence, so an unknown one is never used; CC BY files need a credit, added to the description of every video that uses them (`media.credits`, `used.library_files`). **Bans**: a file can be banned in Settings > Media library (🚫 Ban: never use, `PUT /api/library/{kind}/{name}/ban?on=`, `media.set_banned`; `banned: true` in licences.json, kept when its licence changes) and `_files` never returns it; an uploaded **sound effect whose name has a boom word** (`BOOM_WORDS`: boom, braam, bwaa, hit, rise/riser/uplifter...; `boom_named`) is banned without asking: the user's 'biodynamic impact braam tonal dark' upload matched the `impact` role by name and played on 9 cuts of one video ("banned this ... sound"); `ROLE_WORDS['impact']` no longer includes 'hit'. ## Using this machine's CPU and GPU

Set these in `ai-reels-generator/.env`. They're read by `video.py`:
- `REEL_CONCURRENCY=<cores>`: parallel frame rendering, the biggest speed win.
- `REEL_PARALLEL=2` (Settings: "Videos made at the same time"): this many videos run at once
  across all jobs (a shared semaphore in `pipeline.run`; every job gets its own thread in `server.py`). Claude and download waits overlap; renders still queue on a
  semaphore of `REEL_PARALLEL_RENDERS` (default 1), because two renders fight for the same cores.
  Batch log lines are tagged `[V<n>] `; the app splits them into one row per video.
- **GPU on Windows: `REEL_CHROME=chrome-for-testing` with `REEL_GL` empty.** On the user's laptop (GTX 1650)
  Remotion's default headless shell and every `--gl` value (angle, angle-egl, vulkan) drew in software
  (`npx remotion gpu ...` showed "Software only", WebGL disabled); only the full test browser without `--gl`
  was hardware accelerated (`npx remotion gpu --chrome-mode=chrome-for-testing`). `video.py` and
  `scripts/stills.mjs` then pass only `--chrome-mode=chrome-for-testing`. Check a machine with that command.
- `REEL_GL=egl` (Linux): GPU for the headless browser. If renders come out black or crash, remove it.
- `REEL_HWACCEL=if-possible`: NVENC encoding on NVIDIA GPUs. On machines without a
  usable NVIDIA GPU, Remotion fails instead of falling back, so `video.py` retries once
  without it (and with `--crf` back). `--crf` silently disables NVENC (Remotion falls back to
  libx264), so with hardware acceleration `video.py` drops `--crf` and passes `--video-bitrate`
  (`REEL_GPU_BITRATE`, default 8M long / 12M Shorts). Check Task Manager's "Video Encode" graph.
- Kokoro (offline voice) runs on CPU through onnxruntime. For GPU on Windows you could
  swap in `onnxruntime-directml`. Not done yet: measure first, since voice takes only a
  few seconds anyway.

Where the time goes (measured, 4-core cloud VM): Claude writing 1–1.6 min,
fact-check 1–5 min, voice + footage about 0.6 min, Remotion edit 2.6–3.1 min, Claude
review about 1 min. A failed review costs a whole extra try.

## Traps already hit

- **Remotion browser download**: `remotion.media` can be blocked on restricted networks.
  Set `REEL_CHROME=<path to chrome.exe or chromium>`, which adds
  `--browser-executable ... --chrome-mode=chrome-for-testing`.
- **OneDrive on Windows**: every file there is a reparse point, so Remotion's bundler
  fails with EPERM symlink errors. `remotion/scripts/patch-remotion-windows.js` runs on
  `postinstall`. Rerun it after upgrading Remotion.
- **WinError 5 when finishing a video**: renaming `...-working` to its final name fails on Windows while any file
  inside is open (OneDrive syncing, antivirus). `fsutil.move` retries for ~30 s, then copies. Keeping the project
  outside OneDrive (or `REEL_OUTPUT_DIR` outside it) avoids the locks entirely.
- **Microsoft voice 403**: `speech.platform.bing.com` refuses some cloud IPs. Auto mode
  falls back to Kokoro (the model downloads once, about 350 MB, into `assets/models/`).
- **edge-tts ignores system CAs**: `voice.py` swaps its SSL context for
  `SSL_CERT_FILE` when that's set (for TLS-inspecting proxies).
- **Stock footage can't show named people, specific artifacts or rare animals.** That
  was the #1 review failure. The writer is told to avoid such topics and to query
  close-ups; the reviewer accepts theme-appropriate footage. Pexels reads "football"
  as American football, so use "soccer".
- **Rendered files are big** (CRF 18: 25–45 MB for 30s). Fine for Instagram/YouTube,
  over Telegram's 50 MB bot limit only rarely.
- **Claude usage limits**: a batch can run out of Claude Code usage ("You've hit your session
  limit · resets 10:30pm (UTC)"). `llm.ask` reads the reset time, pauses every video thread at
  its current step until then (+2 min), and retries that same call, so nothing is redone. The
  app shows "Paused till HH:MM". The time zone may be `Asia/Calcutta`, which needs `tzdata`.
  If the app is closed during the pause, the job is lost.
- **moviepy reads `.env` too**, with python-dotenv, and takes `REEL_GL=   # comment` as the value "# comment".
  `reelgen/__init__.py` imports `config` first and `_load_dotenv` overrides values that start with `#`;
  `video.py` ignores them too. Before this, a `.env` copied from `.env.example` could make every Remotion
  render fail and silently fall back to the moviepy edit.
- **A pull without a restart**: the page is read from disk on every load, the Python code only at start, so new buttons answered "Not Found" (FastAPI's own 404 for a route the running app doesn't have; the app's own 404 says "video not found"). `/api/status` `restart_needed` (`_code_stamp`: newest `reelgen/*.py` change vs the one at start) shows an orange "restart the app" bar.
- **`.env` holds keys** (Pexels, optional Anthropic/Telegram). Never print, commit or
  paste it. It's git-ignored.

## The user's standing preferences

- **Accuracy over speed.** Never invent or "adjust" a figure. Graphics numbers must
  match the narration and real sources. No politics or rumours about real people.
- **Videos must not look AI-made:** creator voice, no AI clichés (list in
  `script_writer.py`), real footage, varied pacing.
- **Max 30 seconds**, faster voice.
- **Boom, hit and rise are never used outside the hook** (removed from `sfx.CUE_SOUNDS`, Claude's word cues and the
  automatic sound design in `sound_design.py`). The 7 automatic sounds (whoosh, impact, swish, glitch, shimmer, pop, sad)
  and the user's uploads stay as they are. The cinematic hook (`cinehook.py`) has its own newly synthesised sub boom
  (`sfx.HOOK_SOUNDS`; its riser was banned and removed), because the user asked for the reference video's hook audio; plus one boom under the first
  word of Shorts, Toon and the Shorts Studio. Never add them back to `CUE_SOUNDS`. The same goes for the user's
  uploads: an effect named boom/braam/hit is never used (`media.BOOM_WORDS`), and a file the user bans stays out.
- **Verify, don't assert.** After changing the editor, render a still and look at it;
  after pipeline changes, make one real video and read its `report.json`.
- **Only one session should edit a branch at a time.** Fetch before you push, and never
  force-push over someone else's commits.
